# ZMODEM 上传性能优化（低风险两项）

## 背景

用户反馈 `rz -y` 上传速度仅为 XShell 的 1/10。经分析，上传走的是 native Rust 路径（`ZmodemSender` + inline pump）。核心瓶颈是：**每个 128KB ZMODEM 数据块都同步触发 1 次 Tauri IPC 进度事件**，导致数据泵（pump）循环被频繁打断 + 前端高频 React 重渲染。

## 改动 1：节流上传进度 IPC 事件（核心提速项）

**文件**：`src-tauri/src/ssh.rs`

**问题**：`zmodem_tx.rs:292` 的 `poll()` 每产生一个 128KB subpacket 就 emit 一个 `TxEvent::Progress`。inline pump（`ssh.rs:1109`）对每个 subpacket 调用 `dispatch_tx_events` → `sink.emit("zmodem_progress", ...)`。100MB 文件 = 800 次 IPC（JSON 序列化 + WebView postMessage + React setState + 重渲染），全部在 reader 线程同步执行，打断数据泵连续性。

**方案**：在 `dispatch_tx_events` 中（或调用处）对 `Progress` 事件做时间节流。在 `TxSession` 结构体中加一个 `last_progress_emit: Option<Instant>` 字段，只有距离上次 emit 超过 **100ms** 才真正 emit；不足 100ms 的 Progress 事件被丢弃（最后一个 subpacket / FileComplete / EOF 时强制 flush 一次最终进度，确保进度条能到 100%）。

具体改动点：
- `TxSession` 结构体（`ssh.rs:1286`）新增 `last_progress_emit: Option<Instant>` 字段，`new()` 初始化为 `None`
- inline pump 循环（`ssh.rs:1092-1169`）：不直接调用 `dispatch_tx_events`，改为调用一个新的 `dispatch_tx_events_throttled`，传入 `&mut tx_state.last_progress_emit`，内部对 `Progress` 事件做 100ms 节流
- `WaitingZrinit2`（文件发完）和 `FileComplete` 事件不受节流影响（它们本身频率低），但要确保进入 WaitingZrinit2 前补发一次最终进度（已经由 `zmodem_tx.rs:278` 的 `Progress { sent: size, total: size }` 覆盖，只需保证这个 Progress 不被节流丢弃——在节流逻辑中对 `sent == total` 的最终进度强制放行）

效果：100MB 文件从 800 次 IPC 降到 ~按传输时长/100ms（例如 10 秒传输 = 100 次），减少 8 倍以上。

## 改动 2：移除 sender task 的无效 flush()

**文件**：`src-tauri/src/ssh.rs`

**问题**：sender task（`ssh.rs:758-761`）每次 `write_all` 后都调用 `writer.flush().await`。经确认 russh 0.50 的 `ChannelTx::poll_flush` 是 **no-op**（直接返回 `Ready(Ok(()))`），所以这个调用没有任何实际效果，但每次仍走一遍 async 状态机，对高频小 batch 是纯开销。

**方案**：删除 sender task 循环中的 `writer.flush().await` 调用（保留 `write_all`）。这是零风险改动——flush 本身就是空操作。

## 不改动的部分

- **不改 inline pump 架构**（不开独立 pump task）——历史上独立 task 导致 PTY 缓冲溢出（rz stdin 被淹没 → 字节丢失 → 无限 ZRPOS）。保持 inline 在 `ChannelMsg::Data` 分支推进。
- **不改 `max_packet_size`（32768）和 `window_size`（16MB）**——这些已优化过，不是瓶颈。
- **不改 `SUBPACKET_DATA`（128KB）**——已经是测试过的最佳值。
- **不改 ZDLE 编码 / CRC16**——CRC16 已是查表实现。

## 验证

- `cargo check`（src-tauri/）通过
- `npx tsc --noEmit` 通过（本改动不涉及前端，但确认无回归）
- 手动测试：`rz -y` 上传一个大文件（>50MB），确认速度提升 + 进度条仍正常更新到 100% + 传输完成后无卡死
