# MCP 添加 lrzsz（ZMODEM）支持

## 背景与结论

探索发现：
- **下载方向已有完整原生实现**：`zmodem_rx.rs`（手写 ZMODEM 接收状态机）+ `ssh.rs` 的字节流检测/落盘逻辑全部在核心库 `myshell_core`，零 Tauri 耦合，公开 API 齐全（`zmodem_accept_offer`/`zmodem_send_bytes`/`zmodem_abort`/`zmodem_finish`）。MCP 可直接复用，只需实现 EventSink + 事件编排。
- **上传方向无 Rust 实现**：GUI 走前端 zmodem.js + 文件对话框，无法 headless 复用 → 需新写 Rust ZMODEM 发送状态机（参考 `node_modules/zmodem.js/src/` 源码与 `zmodem_rx.rs` 风格）。
- `sz`/`rz` 必须在 PTY shell 中运行 → 工具内部用 `ssh::connect()`（交互式会话，自动带 PTY + 整套检测状态机），而非 exec channel。
- MCP 已有完整 `AppState`（含 `ssh_sessions`），凭据经 `resolve_via_gui` 获取，架构上无障碍。

## 变更清单

### 1. 新文件 `src-tauri/src/zmodem_tx.rs`（核心，约 900 行）

ZMODEM **发送方**状态机，纯同步、不碰 async/Tauri，风格对齐 `zmodem_rx.rs`：

```rust
pub struct ZmodemSender::new(name: String, size: u64, mtime: u64)
pub fn feed(&mut self, data: &[u8]) -> TxActions      // 解析远端 rz 的帧
pub fn poll(&mut self, file: &mut fs::File) -> TxActions  // 按状态推进（读文件、产字节）
pub struct TxActions { pub send: Vec<u8>, pub events: Vec<TxEvent> }
pub enum TxEvent { Started, Progress{sent,total}, FileComplete{...}, SessionEnd, Error(String) }
```

状态流：`WaitingZrinit`（收 ZRINIT，取 window/flags）→ 发 ZFILE（`name\0size mtime mode serial files` 元数据）→ `WaitingZrpos` → 发 ZDATA 头 + 文件数据子包（ZDLE 转义 + CRC16）→ ZEOF → 等 ZRINIT → 发 ZFIN → 收 ZFIN → 发 "OO" → `SessionEnd`。

协议决策（保证与 lrzsz `rz` 兼容）：
- 统一用 **ZBIN/CRC16**（发送方可选 CRC16，即使接收方声明 CANFC32），避免实现 CRC32；
- 窗口流控：按 ZRINIT 声明的 window 发 ZCRCG 流式子包 + ZCRCW 收尾等 ZACK；收到 ZRPOS 则 seek 重传；
- 处理 ZSKIP/ZFERR/CAN×5 中止；
- 复用 `zmodem_rx` 的常量与 CRC：把其 `frame_type`/`subpkt_end`/`ZDLE`/`ZPAD`/`ZBIN`/`ZHEX`/`XON`/`XOFF`/`crc16_xmodem`/`offset_bytes` 改为 `pub(crate)`（zmodem_rx.rs 小改）。

### 2. `src-tauri/src/lib.rs`（一行）

`pub mod zmodem_tx;`

### 3. `src-tauri/src/bin/myshell-mcp.rs`（主要改动）

**新增 `McpSink`**：实现 `EventSink`，把 `(event, payload)` 转发进 `tokio::sync::mpsc::UnboundedSender`（参考 CLI 的 `CliSink`）。

**新增工具 `zmodem_download`**（远端 `sz` → 本地）：
- 参数：`connection`、`remote_path`（远端文件）、`local_dir`（本地目标目录）、`timeout`（默认 120s）
- 流程：`resolve_via_gui(conn, Some("ssh"))` → 检查本地目录 → `ssh::connect(McpSink)` 开会话 → `send_input("sz '<path>'\r")`（路径单引号转义）→ 事件循环：
  - `zmodem_offer{fileName,fileSize}` → **basename 清洗防路径穿越**（fileName 来自不可信远端，剥目录成分/`..`/非法字符）→ `local_dir\fileName` → `ssh::zmodem_accept_offer(Some(path))`
  - `zmodem_file_complete` 记录 → `zmodem_end` 完成 → `zmodem_error`/`ssh_closed` 报错
  - 超时 → `zmodem_abort` + 报错（附捕获的终端输出，提示可能未安装 lrzsz）
- 收尾：`ssh::disconnect`（出错路径也保证执行）；返回 `{files:[{name,local_path,bytes}]}`
- **不弹确认框**（对齐 `sftp_download`）

**新增工具 `zmodem_upload`**（本地 → 远端 `rz`）：
- 参数：`connection`、`local_path`（本地文件）、`remote_dir`（远端目标目录）、`timeout`（默认 120s）
- 流程：`confirm_dangerous_operation` 弹原生确认框（对齐 `sftp_upload`，写远端必确认）→ 读本地文件元数据 → `ssh::connect` → `send_input("rz -y\r")`（`-y` 覆盖已存在文件，避免 rz 交互式询问卡死）→ 事件循环驱动发送方：
  - `zmodem_raw{data}` → `sender.feed(bytes)` → 输出经 `ssh::zmodem_send_bytes` 回写
  - 交替 `sender.poll(&mut file)` 推进数据发送
  - `TxEvent::SessionEnd` → `ssh::zmodem_finish` → 完成；Error/超时 → `zmodem_abort` + 报错
- 收尾 disconnect；返回 `{remote_path, bytes}`

**工具定义**：`tool_definitions()` 按现有详细风格补两个工具描述（WHEN TO USE：远端无 SFTP 子系统/受限 shell/跳板机场景；要求远端装有 lrzsz；大文件调大 timeout）；`SERVER_INSTRUCTIONS` 补一句：文件传输优先 sftp_*，SFTP 不可用时用 zmodem_*。

## 关键风险与对策

| 风险 | 对策 |
|---|---|
| 远端未装 lrzsz → 无 ZMODEM 启动序列 | 等待 `zmodem_start` 设较短首帧超时（~15s），超时错误信息附终端输出并提示安装 lrzsz |
| `zmodem_offer` 的 fileName 是攻击面 | basename 清洗，只落盘到指定 local_dir |
| 工具中途出错泄漏会话 | 编排封装 cleanup，所有路径保证 `ssh::disconnect` |
| 发送方与 lrzsz 兼容性 | CRC16/ZBIN 保守配置 + ZRPOS 重传支持；参考 zmodem.js sender 行为实现 |
| conn_type=sftp 的连接无 shell | `resolve_via_gui(_, Some("ssh"))` 天然排除 |
