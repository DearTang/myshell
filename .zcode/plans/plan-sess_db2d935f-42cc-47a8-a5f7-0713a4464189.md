# 实现计划：日志脱敏 + 左下角反馈入口

## 方案总览

三大模块，遵循项目既有 IPC 契约（main.rs command → api.ts wrapper → 组件）和样式约定（inline styles + CSS vars）。

```
① 日志脱敏 (Rust)        ② 暴露日志给前端 (Rust command)      ③ 反馈入口 + 弹窗 (前端)
ssh.rs/ftp.rs/proxy.rs   get_feedback_log (返回脱敏日志)      Sidebar 加"反馈"行
   ↓ 脱敏过滤层           reveal_path (打开文件夹)            FeedbackDialog 组件
host/user/proxy 掩码      　                                   截图/选图→本地zip
                                                            Web3Forms POST (后实测)
```

## 模块①：日志脱敏（Rust 后端）

**现状**：密码/密钥本就不记录（已安全）。但 `ssh.rs:272`、`ftp.rs:49/75`、`proxy.rs` 记录了主机名、用户名、代理地址，属于隐私信息。

**改动**：

1. **`src-tauri/src/main.rs`** 新增 `redact.rs` 风格的脱敏工具函数（放 main.rs 或新建小模块），提供：
   - `redact_host(host)` → 保留首尾，中间掩码：`192.168.1.10`→`1*.10`，`myserver.com`→`m******m`
   - `redact_user(user)` → 首尾可见：`root`→`r**t`，`admin`→`a***n`
   - IP 地址特殊处理：保留前一段+最后一段，中间掩码
   - 短字符串（≤2字符）整体掩码为 `***`

2. **`src-tauri/src/ssh.rs:272`** 修改连接日志：
   ```rust
   // 改前
   log::info!("[ssh] dialing via {} proxy {}:{} → {}:{}",
       config.proxy_type, proxy_cfg.host(), proxy_cfg.port(), config.host, config.port);
   // 改后
   log::info!("[ssh] dialing via {} proxy {}:{} → {}:{}",
       config.proxy_type,
       redact::host(proxy_cfg.host()), proxy_cfg.port(),
       redact::host(&config.host), config.port);
   ```

3. **`src-tauri/src/ftp.rs:49`** 和 **`ftp.rs:75`** 同样处理：
   - `[ftp] connecting to {}:{}` → host 脱敏
   - `[ftp] TCP established, logging in as {}` → username 脱敏

4. **FTP 错误提示 `ftp.rs:61`** 含 `cfg.host` → 脱敏（这是给用户看的错误，但会进日志）

**原则**：端口保留（非隐私，且排查有用）；密码/密钥维持现状不记录。

## 模块②：暴露日志给前端（Rust command + api.ts）

**现状**：日志写在 `<config_dir>/myshell/logs/myshell-<date>.log`，但前端完全读不到（`read_text_file` 被 PEM 标记卡死，`read_file_base64` 返回 base64 不适用）。

**改动**（三处同步，遵循 AGENTS.md IPC 契约）：

1. **`src-tauri/src/main.rs`** 新增 2 个 `#[tauri::command]`：

   - `get_feedback_log()` → `Result<FeedbackLogInfo, String>`
     - 重新计算 `dirs::config_dir().join("myshell").join("logs")`（与 setup_file_logging 同逻辑）
     - 读取当天日志文件 + 前 1 天（覆盖跨天场景），合并
     - **二次脱敏**：对读取出的日志文本再做一遍正则脱敏（防住历史已写的未脱敏日志，以及 russh/第三方库自身的日志）
     - 截断到合理上限（如最后 200KB，避免邮件过大）
     - 返回结构：`{ log_dir: String, content: String, truncated: bool }`
     - debug 构建（无文件日志）返回空 content + 提示

   - `reveal_path(path: String)` → `Result<(), String>`
     - 仅允许 `myshell/logs` 目录路径（白名单校验，拒绝任意路径）
     - Windows: 用已注册的 `tauri_plugin_shell` 执行 `explorer.exe <path>`（与 open_external_url 同插件，不引新依赖）
     - 其他平台: `open` 命令

2. **`main.rs` `generate_handler!`**（在 `ai_test_settings,` 后、`])` 前，约 3241 行）注册这两个命令

3. **`src/api.ts`** 新增类型 + wrapper（与 readTextFile 同范式）：
   ```ts
   export interface FeedbackLogInfo { logDir: string; content: string; truncated: boolean; }
   export async function getFeedbackLog(): Promise<FeedbackLogInfo> {
     return await invoke("get_feedback_log");
   }
   export async function revealPath(path: string): Promise<void> {
     return await invoke("reveal_path", { path });
   }
   ```

## 模块③：反馈入口 + 弹窗（前端）

### 3a. Sidebar 入口（`src/components/Sidebar.tsx`）

在 version footer（789行）上方加一个"反馈"行，镜像现有 footer 结构（flex row + borderTop + hover）：
- emoji 图标（如 💬 或 📮）+ "反馈" 文字（fontSize: 11, var(--text-tertiary)）
- `onClick={() => onOpenFeedback?.()}`
- 新增 prop `onOpenFeedback?: () => void`（与 onOpenAbout 同范式，可选调用）

### 3b. FeedbackDialog 组件（`src/components/FeedbackDialog.tsx` 新建）

**结构**（镜像 AboutDialog.tsx — 同样的 overlay/backdrop/animate-scale-in/btnPrimary/btnGhost，textarea 镜像 AiPanel.tsx:524）：

- **overlay**：`position:fixed; inset:0; var(--bg-overlay); zIndex:2100; backdropFilter:blur(8px)`，backdrop click 关闭
- **面板**：`width:560; maxWidth:92vw; maxHeight:86vh; display:flex; flexDirection:column`，`onClick={stopPropagation}`，`animate-scale-in`
- **ESC 关闭**：`useEffect` keydown 监听（项目里首个，但符合直觉）

**内容区（可滚动 body）**：
1. **反馈类型**（select 或 radio）："问题报告 / 功能建议 / 其他"
2. **描述**（textarea，必填，镜像 AiPanel textareaStyle）
3. **图片**（截图 + 本地选图）：
   - "截图"按钮：调用 `getDisplayMedia` 截屏 → 转 PNG blob → 预览
   - "选择图片"按钮：用已集成的 `@tauri-apps/plugin-dialog` 的 `open({ filters: [{name:'图片', extensions:['png','jpg','jpeg']}] })`
   - 缩略图预览区，可删除
4. **日志**（自动附加，可展开查看/编辑）：
   - 打开弹窗时调 `getFeedbackLog()` 拿到日志内容（已脱敏），存 state
   - 显示 "已附加日志（X KB）" + 展开查看按钮（可折叠的 <pre>）
   - 用户可选择不附加（复选框）

**提交逻辑**：
1. 收集：反馈类型 + 描述 + 环境信息（version=props.version, platform=navigator.platform, userAgent）
2. **图片 → 本地 zip**：用浏览器 `CompressionStream` 不可行（无zip），改为：把图片存到临时文件（调 Rust 写文件 command）或打包成 zip（需轻量 zip 库如 `fflate`，~8KB）。存到日志目录旁的 `feedback/` 子目录，文件名带时间戳。
3. **Web3Forms POST**（前端 fetch，不用 reqwest 以规避服务端拦截）：
   ```ts
   const body = {
     access_key: WEB3FORMS_KEY,  // 写在常量/配置
     subject: `[MyShell反馈] ${type} - v${version}`,
     from_name: "MyShell 反馈",
     message: 描述,
     feedback_type: type,
     app_version: version,
     platform: navigator.platform,
     log_content: 日志内容,  // 文本内联，免费版支持
   };
   await fetch("https://api.web3forms.com/submit", {
     method: "POST",
     headers: { "Content-Type": "application/json" },
     body: JSON.stringify(body),
   });
   ```
4. **结果反馈**：
   - 成功：显示"反馈已提交，感谢！"，提示"如需附加截图，反馈包已保存在 X，点此打开文件夹"
   - 失败（含 Origin 拦截的 403）：显示错误 + "已生成本地反馈包（含日志+截图），路径 X，点此打开文件夹，可手动发送"

**配置**：Web3Forms access_key 放在 `src/config.ts` 或 FeedbackDialog 顶部常量，后续填入实测可用的 key。

### 3c. App.tsx 接线（`src/App.tsx`，镜像 SettingsPanel/AboutDialog 模式）

1. import：`import { FeedbackDialog } from "./components/FeedbackDialog";`（12行附近）
2. state：`const [showFeedback, setShowFeedback] = useState(false);`（53行附近）
3. Sidebar prop：`onOpenFeedback={() => setShowFeedback(true)}`（604-633行 Sidebar 块内）
4. 渲染：`{showFeedback && (<FeedbackDialog version={appVersion} onClose={() => setShowFeedback(false)} />)}`（836行后）
