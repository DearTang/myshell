# MyShell 统一界面架构设计

> 版本：v1.0（2026-09-12）
> 适用范围：`src/` 前端（React 18 + TypeScript + Tauri v2）
> 原则：**渐进式演进，零功能破坏**——所有重构均为"绞杀式"迁移，任一阶段结束后应用均可正常构建与使用。

---

## 一、现状盘点

### 1.1 功能全景（界面视角）

| 功能域 | 承载界面 | 主要组件 |
|---|---|---|
| 保险库 / 主密码门 | 全屏门禁层 | `MasterPasswordGate` |
| 连接管理 | 左侧边栏（树 + 搜索 + 拖拽） | `Sidebar`, `ConnIcon` |
| 会话标签 | 顶部标签栏 + 会话/广播面板 | `TabBar`, `SessionDropdownPanel` |
| 终端 | 中央工作区 | `TerminalPanel`, `CommandBar`, `ZmodemProgressOverlay` |
| 文件浏览 | 中央工作区（SFTP tab） | `SftpPanel` |
| 多窗口模式 | 网格布局工作区 | `MultiWindowPicker` |
| 服务器监控 / AI 助手 | 右侧面板 | `ServerInfoPanel`, `AiPanel` |
| 设置中心 | 全屏面板（左类目右内容） | `SettingsPanel`（165KB 巨石） |
| 对话框群 | 全局浮层 | `ConnectionDialog`/`AboutDialog`/`FeedbackDialog`/`RecycleDialog`/`BroadcastDupDialog`/`StatsConsentDialog`/`PasswordVerifyDialog`/`ConfirmDialog`/`QuickCommandsPanel` |
| 通知 / 更新 | 浮层卡片 | `UpdateNotification`, Toast（散落实现） |
| 品牌视觉 | 侧栏底部 | `BrandLogo`, 版本号 / 反馈入口 |

### 1.2 技术形态

- React 18 + TS + Vite，**无 UI 框架、无路由库、无状态管理库**（纯 useState/useEffect）。
- 样式：单一 `styles/global.css`（约 12KB，设计令牌 + 少量通用类）+ `themes.ts`（33KB 配色预设）+ **大量内联样式**（SettingsPanel 内联样式 247 处 vs className 3 处；App.tsx 45 处内联、0 处 className）。
- 状态：`App.tsx`（102KB）集中持有 28 个 useState，props 层层下钻；所有对话框在 App.tsx 挂载与开关。
- IPC：`api.ts` 单文件 55KB，承担全部 Tauri command 封装 + 类型定义 + 事件订阅。
- 主题：CSS 变量挂 `:root/[data-theme]`，`useTheme`/`useColorScheme` 通过 `setProperty` 动态覆盖。机制健康，保留。

### 1.3 核心痛点

1. **巨石组件**：SettingsPanel（约 4000 行、72 个 useState）、App.tsx 无法安全迭代；改一处全量重渲染。
2. **无基础组件层**：Button / Input / Select / Dialog / Toggle / List 每处各自手写，视觉一致性靠人肉对齐；内联样式无法表达 `:hover` / 媒体查询 / 复用，也使主题变量使用零散。
3. **浮层无统一管理**：9+ 个对话框的开关状态、z-index、确认/取消语义各自为政，Esc / 遮罩行为不统一（部分防误关、部分不是）。
4. **状态无边界**：连接、标签、终端、传输、设置、UI 状态混在 App.tsx，任何功能都要动 App.tsx。
5. **api.ts 单文件**：类型、命令封装、事件订阅混在一起，前后端契约不清晰。

## 二、设计目标与原则

**目标**：建立一套可支撑 MyShell 未来 2-3 年功能迭代（更多面板、更多协议、MCP 深化、跨平台）的统一界面架构。

**原则**：

1. **令牌先行**：一切颜色 / 间距 / 圆角 / 动效来自 Design Token，禁止出现硬编码色值。
2. **组件分层**：base（无业务）→ feature（业务复合）→ panel（页面级），只允许下层引用上层。
3. **状态按域拆分**：每个状态域一个 Provider/Store，App.tsx 只做组合与布局。
4. **浮层系统统一**：所有对话框/抽屉/Toast 走同一个 Overlay 调度器，统一 z-index、Esc、焦点、防误关语义。
5. **IPC 契约显式化**：按域拆分 api 模块，类型单一来源。
6. **不放宽安全边界**：CSP 白名单、命令确认等安全机制不因架构调整放松；样式方案不引入运行时 CSS-in-JS 以维持 CSP 下的可预测性。

```
├──────────┴──────────┴───────────────────┴───────────────────┤
```

## 四、视觉设计系统（Design Tokens）

现有 `global.css` 的令牌体系（bg 分层 / text 四级 / accent / 语义色 / border 三级 / shadow 五级 / glass / 缓动 / radius）是良好底座，统一扩展为完整规范：

### 4.1 令牌清单（在现有基础上补齐）

| 类别 | 现有 | 新增 |
|---|---|---|
| 色彩 | `--bg-*` `--text-*` `--accent-*` `--success/warning/error/info` | `--accent-tertiary`（连接类型色：ssh 主蓝 / sftp 副青 / ftp 黄 / local 灰，收编现有散落写法） |
| 间距 | 无（各处手写 4/8/12px） | `--space-1..8`：4/8/12/16/20/24/32/48 |
| 字号 | 无 | `--font-xs/sm/md/lg/xl`：12/13/14/16/20 |
| 行高/字重 | 无 | `--leading-*`、`--font-medium/semibold` |
| 层级 | 无 | `--z-*`（见 4.3） |
| 动效 | `--duration-*` `--ease-*` | 统一"仅 transform/opacity 参与 transition"约定 |

### 4.2 样式组织

- **保留 CSS 变量 + `data-theme` 切换机制**（它已经支撑深浅主题与配色预设，且对 CSP 友好）。
- Base 组件样式写入按组件拆分的 CSS 文件（`ui/Button.css` 等），Vite 天然支持；**不引入运行时 CSS-in-JS**。
- 迁移期内联样式仅允许"动态值"（如拖拽宽度、进度百分比），静态外观一律迁到类 + 令牌。
- `themes.ts` 保持"终端 ANSI + UI 变量覆盖"职责不变，新增变量须同步登记到两套预设。

### 4.3 z-index 层级表（全局唯一裁决处）

| 层 | 变量 | 值 | 用途 |
|---|---|---|---|
| 工作区 | `--z-workbench` | 0 | 终端 / SFTP / 网格 |
| 侧栏/顶栏 | `--z-chrome` | 10 | Sidebar / TabBar / StatusBar |
| 右侧面板 | `--z-side-panel` | 20 | AI / ServerInfo |
| 悬浮卡 | `--z-floating` | 30 | 更新提示卡 / 传输进度浮层 |
| 抽屉 | `--z-drawer` | 40 | 设置面板（全屏覆盖） |
| 遮罩 | `--z-overlay` | 50 | 模态遮罩 |
| 对话框 | `--z-dialog` | 60 | 全部模态对话框（栈内递增） |
| Toast | `--z-toast` | 70 | 通知浮层 |
| 保险库门禁 | `--z-vault` | 80 | MasterPasswordGate |

## 五、Base 组件库（`src/ui/`）

从现有巨石中抽取的最小必要集合（每个组件 ≤300 行，API 全部受控式）：

| 组件 | 来源/统一对象 |
|---|---|
| `Button`（variant: primary/secondary/ghost/danger; size; loading） | 各面板的渐变主操作、取消/保存 |
| `Input` / `TextArea`（label、必填星号、错误态抖动） | ConnectionDialog 必填校验、设置表单 |
| `Select` / `FontField`（模糊搜索下拉、键盘导航） | 字体选择、预设模板下拉 |
| `Dialog`（受控开关、防误关遮罩选项、Esc、焦点陷阱、危险二次确认） | 9 个对话框的公共壳 |
| `ConfirmDialog`（升级为通用 confirm：danger 标记、MCP 危害列表模式） | 删除确认 / 命令确认 |
| `Toast`（success/error/info，顶部居中，队列） | 散落的"已保存"提示 |
| `Toggle` / `Slider` / `NumberField` | 设置面板全部开关 |
| `Tree`（展开/收起、长按拖拽、空态） | Sidebar 连接树 |
| `Tabs` / `SegmentedControl` | 设置分类、传输模式 |
| `Panel` / `Section` / `FieldRow` | 设置左右分栏、表单分组 |
| `Badge` / `StatusDot`（在线/离线/异常） | TabBar 连接状态 |
| `EmptyState`（图标 + 文案 + 主操作） | 列表空态统一 |
| `Spinner` / `ProgressBar` | 传输进度、下载进度 |

Base 组件只消费令牌；暗/浅主题与配色预设自动生效，无需各自适配。

```css
.app-shell {
  display: grid;
  grid-template:
    "tabbar tabbar  tabbar"  auto
    "side   work    right"   1fr
    "status status  status"  auto
```

终端实例（xterm 对象、数据管道、resize）是**非 React 状态**，继续由 TerminalPanel 以 ref 自持；Store 只持有"会话元数据"（tab 列表、状态、广播组）。禁止把 xterm 实例放入 React state。

## 七、状态管理架构

不引入重型状态库，采用 **Context + useReducer 按域拆分**（未来可平替为 zustand，API 面一致）：

| Store | 职责 | 关键状态 |
|---|---|---|
| `VaultStore` | 保险库门禁 | locked / unlocked / 初始化态 |
| `ConnectionStore` | 连接与文件夹 CRUD、回收站 | 列表、树、搜索词、拖拽态 |
| `SessionStore` | 标签页编排 | tabs、activeTabId、广播组、会话下拉 |
| `TransferStore` | 传输任务 | SFTP/ZMODEM 进度浮层、取消令牌 |
| `SettingsStore` | 全部设置项持久化 | 外观、AI、安全、快捷命令、MCP、传输 |
| `UiStore` | 界面瞬时态 | 侧栏宽度、面板折叠、Toast 队列 |

规则：

- Store 之间只允许"读快照 + 订阅事件"，禁止互相 setState 形成环。
- Tauri 后端事件（`ssh_output`、`zmodem_progress`、`mcp_exec_result`…）由 `events/` 事件桥统一订阅后分发给对应 Store，组件不再各自 `listen`（消除现有"前端监听就绪前的 banner 字节丢失"这类时序 bug 的土壤）。
- 设置持久化统一走 `SettingsStore` 的 `persist()`，localStorage key 全部登记在 `settings/keys.ts`。

## 八、浮层与对话框统一调度

`overlay/OverlayProvider` 作为唯一浮层入口：

```ts
// 命令式 API，替代 App.tsx 里 9 组 useState 开关
overlay.open(<ConnectionDialog />, { modal: true, dismissable: false });
overlay.confirm({ title, body, danger, reasons });   // 返回 Promise<boolean>
overlay.toast("已保存", "success");
```

- 统一 z-index 栈、统一 Esc 处理（从栈顶弹出）、统一焦点归还。
- 统一"防误关"语义：表单类对话框默认 `dismissable: false`（对齐现有行为）。
- MCP 命令确认（黑名单危害说明 + 置顶闪烁）是 ConfirmDialog 的一个变体，逻辑下沉到调度器而非各处复制。

## 十一、渐进迁移路线

每阶段独立可交付，完成后跑 `npm run test:ts` 静态检查即可（遵循本项目"不跑构建"约定）。

**Phase 1 — 打地基（无行为变化）**
1. `styles/global.css` 拆出 `tokens.css`，补齐间距/字号/z-index 令牌。
2. 建立 `ui/` 空层，先迁 3 个高频组件：`Button`、`Toast`、`ConfirmDialog`。
3. `api.ts` 按第九节拆分，`api.ts` 保留为 re-export 桶。

**Phase 2 — 浮层与状态收口**
4. 引入 `OverlayProvider`，9 个对话框逐个接入（每迁一个删一组 App.tsx useState）。
5. 建立 5 个 Store，先把 `UiStore`（宽度/折叠）和 `SessionStore`（tabs）从 App.tsx 迁出。

**Phase 3 — 巨石拆解**
6. SettingsPanel 按设置类目拆为 `panels/settings/*`（每类目一文件，共享 `Section/FieldRow`），165KB → 每文件 ≤500 行。
7. Sidebar 拆出 `features/connection-tree`（树 + 搜索 + 长按拖拽），`useConnectionDrag` 随迁。
8. App.tsx 缩减为 `AppShell`：只做布局组装、Provider 挂载、全局快捷键，目标 ≤300 行。

**Phase 4 — 令牌全覆盖**
9. 新代码强制走 Base 组件；存量内联样式按面板逐步替换为类名（静态值），动态值保留内联。
10. 交付文档：`docs/ui/` 组件用法示例 + 令牌速查表。

**验收口径（每阶段通用）**：tsc 零错误；主题深/浅 + 任一配色预设切换无破样；任一对话框 Esc/遮罩行为符合第八节语义；终端数据流、ZMODEM、MCP 确认等安全路径行为不变。

## 十二、边界与不变量

- **安全不变**：CSP 白名单不放宽（故不用运行时样式注入方案）；密码/MCP 确认路径只做 UI 层重组，逻辑与后端契约零改动。
- **性能不变量**：终端输出零 React 状态化；Store 拆分后 AppShell 级重渲染只发生在 tab/面板结构变化时。
- **兼容不变量**：localStorage key、Tauri command 名、事件名、配置文件位置全部保持不变，用户无感升级。
